Work

What I work on.

Roughly four areas, with the project each one comes from.

  1. BACKEND

    Backend work in regulated systems

    At Bitpanda I owned the crypto address book: the API, the data model, the validation rules, the tests and the release. In custody, an address accepted by mistake can mean funds nobody gets back, so most of the work sat in the validation and the failure cases rather than the happy path.

    Project Bitpanda — institutional crypto custody for banks.

  2. MIGRATION

    Legacy Java into Node and NestJS

    At RWE we moved legacy Java components to NestJS in slices, with integration and E2E tests around each slice, so day-to-day delivery could keep going while the migration ran underneath it. Small team, live production system, no appetite for a full rewrite.

    Project RWE — Java to NestJS on an energy-market platform.

  3. PERFORMANCE

    APIs and data access that got slow

    I profile before changing anything. At RWE that meant finding the real bottleneck in MongoDB aggregations serving about 15,000 queries a day, then moving CPU-heavy exports onto Node worker pools so they stopped blocking normal API work.

    Project RWE — around 65% faster API responses; exports from 45 minutes to 12.

  4. PRODUCT

    Product work across React and Node

    React and Node in the same week, usually with somebody else's platform in the middle. At ImmoScout24 that was Iterable wired into lifecycle messaging — mostly mapping their data model onto ours and making the failure modes visible. The platform was tested at every layer and matching that bar took me a while.

    Project ImmoScout24 — Iterable lifecycle integration, plus search, listing and SEO across React and Node.
