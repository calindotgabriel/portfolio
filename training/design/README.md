# design/

Câte un fișier per prompt: `01-idempotent-webhooks.md` … `10-zero-downtime-migration.md`.

Fiecare prompt are două ședințe și fișierul crește în două runde:

**Runda 1 (oarbă)** — 40 min la tablă cu voce tare, fără să te uiți la nicio referință. Scrii ce ai
produs, urmând cadrul de 7 pași: cerințe → cifre de scală → API → model de date → componente →
**moduri de eșec** → trade-offs.

**Runda 2 (după referință)** — compari cu Alex Xu / ByteByteGo / DDIA și scrii exact trei lucruri pe
care le-ai ratat. Nu mai mult de trei; o listă lungă nu se reține.

Cele trei lucruri ratate se adună în timp. Dacă același tip de omisiune apare la patru prompturi
diferite — de obicei modurile de eșec sau cifrele de scală — ăla nu e un gol de cunoștințe, e o
lipsă din cadru, și se repară exersând cadrul, nu citind mai mult.
