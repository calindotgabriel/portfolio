## Evidence Boundaries

### Verified evidence

- Bitpanda: Calin strengthened authentication between services on an AWS-based institutional crypto-custody platform for banks and introduced backend testing patterns adopted by the team.
- RWE: Calin profiled a MongoDB-backed workflow and used MongoDB-path improvements and worker pools to reduce export time from 45 minutes to 12 minutes; API response times also improved by 65%.
- PostgreSQL appears in the resume's database skill list.
- No supplied source ties PostgreSQL to a named project, ownership scope, performance investigation, metric, or result.
- The call-feedback signal is fictional, singular, and has no supplied funnel outcome.

### Hypotheses

- Some PostgreSQL-heavy buyers may require engine-specific production proof rather than a transferable database-performance method.
- A privately verified, tightly calibrated answer could make Calin's actual PostgreSQL depth clearer without weakening the stronger Bitpanda authentication proof.
- If no concrete PostgreSQL story can be verified, explicitly separating PostgreSQL familiarity from MongoDB performance proof may preserve trust better than forcing a weak example.

### Unknowns

- Whether Calin has an unrecorded PostgreSQL example he can substantiate and disclose.
- The project, production context, workload, personal ownership, actions, tools, result, and disclosure limits of any such example.
- What level of PostgreSQL depth the fictional interviewer expected or how the answer would affect a decision.
- Whether this request recurs in real qualified opportunities.

## One Proposed Improvement

Create one **private, gated PostgreSQL proof-verification and calibrated-answer module** for interview preparation.

The module may admit a concrete PostgreSQL example only if Calin personally confirms every required field: project, production context, PostgreSQL workload, personal ownership, problem or goal, diagnostic/action details, result, and disclosure boundary. Each admitted fact must be traceable to Calin's confirmation; no metric or outcome may be inferred.

If any field is missing, the same module must use the no-claim path: state only that PostgreSQL is a listed skill, identify the quantified RWE example as MongoDB-based, and discuss the measurement-first investigation method without presenting it as PostgreSQL experience. The module must not rename, generalize, or transplant the RWE result.

This is one gated improvement, not a new public story and not a rewrite of the Bitpanda-led position.
